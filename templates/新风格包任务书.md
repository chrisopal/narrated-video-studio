# 新风格包任务书

把一种画面风格做成工坊自己的风格包时用这份任务书。可以自己照着做，也可以交给一个独立的 agent（几套风格可以同时交给几个 agent 并行做，每个只写自己的三处文件）。交出去时，在这份任务书后面附一段**任务说明**，写清：

- id（英文小写，同时是包文件名、主题名、样片目录名）和中文名
- 用在什么题材
- 画面规则（从 `templates/风格模板.md` 里那一行展开：识别特征、必须做到的、不许做的）
- 招牌组件建议（3–6 个，带大致的参数）
- 样片题目（中性、不需要查证的小题目）

做完以后由交任务的人：逐张看样片定格；在 `kit/gallery/gallery.json` 加一条（样片名 + 5 个定格时刻）并 `python3 kit/workshop.py gallery <名字> --accept`；把包写进 `templates/风格包.md` 和 `templates/风格模板.md`；`workshop.py add` 登记为候选。

## 任务：给“讲解视频工坊”做一套新的风格包（自己实现）

工坊是一个用 HTML canvas 逐帧画讲解视频的工具箱。仓库在 `<工坊>`（`kit/` 引擎、`templates/` 文档）。
你要做的是**一个风格包**：一个 JS 文件 + 一条能跑的小样片。风格的名字、id 和画面规则在给你的任务说明里。

## 必读（先读再写）
- `<工坊>/SKILL.md` 第 9 节（分场）和第 10 节（检查）
- `<工坊>/kit/kit.js`（全局：`W H g cv TH`，`cl seg lerp eo eio expo back rnd`，`txt tw rr pop rise glow pill dash arrow card fadeIO scn sfx`，`T N at`，`addTheme`，主题结构看 `THEMES` 和 `TDEF`）
- `<工坊>/kit/components.js`（现成通用组件的写法）
- `<工坊>/templates/风格包.md`、`templates/风格模板.md`
- 例子：`kit/packs/litho.js` 末尾的“接合”部分怎么登记主题；`kit/gallery/map/` 是一条完整的无旁白样片（brief.json / script.json / scenes.js / facts.json）

## 产出（只许写这三处，别的文件一律不要改）
1. `<工坊>/kit/packs/<id>.js`
2. `<工坊>/kit/gallery/<id>/`：`brief.json` `script.json` `scenes.js` `facts.json`（内容写 `[]`）
3. `<工作目录>/<id>/`：你的试验项目（先在这里做，做好了把四个文件拷到第 2 处）。在这个目录里运行命令：`python3 ../kit/build.py stills 3,9,15 [目录]`、`python3 ../kit/build.py check`

不要改 `kit.js`、`components.js`、`build.py`、`workshop.py`、`film.html`、`gallery.json`、`templates/`、别人的包。不要运行 `workshop.py gallery`（会和别人冲突）。不要运行 render / mix / final。不要联网下载任何东西。发现引擎有缺陷：写进报告，不要自己改。

## 风格包文件的格式
```js
/* 风格包 · <中文名> —— 本项目自己实现
   用法：…（每个导出函数一行：签名 + 干什么） */
window.PACK=window.PACK||{};window.PACK_INIT=window.PACK_INIT||[];
PACK.<id>=(function(){
  // 只用 kit.js 的全局和 canvas 2D；需要缓存的大图用离屏 canvas 做一次
  addTheme('<id>', { light:…, ink, dim, note, a1, a2, a3, chip, sub, subInk, top, bot, card, cardInk, pillInk, hl, f:{t,b,s,h,n}, bg(t){…}, post(t){…可选} });
  function …
  return { … };
})();
```
- 主题色要成体系：`ink` 正文色、`a1` 主强调、`a2` `a3` 辅助；通用组件会用这些色，所以要保证在你的底色上读得清。
- 可用字体：`H5 H7 H9`（思源黑体 500/700/900）、`KT`（霞鹜文楷，手写感）、`RC`（Roboto Condensed，数字）、`Song` `SongB`（宋体）。不要引用别的字体。
- 导出 3–6 个“招牌组件”：就是让这个风格一眼认得出来的那几样东西，做成带参数的函数（位置、文字、时刻、进度都是参数，不要把样片内容写死在包里）。时间参数的习惯：`(t, t0, …)`，t 是全片时间，t0 是开始时刻。
- **所有文字必须走 `txt()`**（或和它等价地调用 `recText`），这样检查才看得见；需要旋转/缩放就先变换再 `txt`。
- 一切动画都是 `t` 的确定函数：不用 `Math.random()`、`Date`，随机用 `rnd(整数)`。同一个 t 画两遍必须一模一样。
- 每帧不要做逐像素循环；纹理、纸张、噪点这类东西用离屏 canvas 预先做一次。
- scenes.js 整份包在 `(() => { const {…} = PACK.<id>; window.FILM = {…}; })();` 里。

## 样片
- 无旁白：`script.json` 每句写 `{"id":"a0","ch":"章名","silent":true,"dur":秒数}`，4–5 句，总长 24–32 秒。`brief.json`：`{"title":"风格包样片·<中文名>","genre":"测试","style":"<id>","packs":["<id>"],"sfx":false}`。
- `FILM` 里 `theme:'<id>'`，`chrome:'none'` 或合适的章节条；`cover` 要有（`pill title line1 line2 tagline art(c,cx,cy,R){}`）。
- 样片要把这个风格的**画面语法**演出来：每一句对应一个典型镜头，把招牌组件都用到。内容自己编一个中性的小题目（比如“一杯水怎么烧开”“快递怎么分拣”“桥为什么要有拱”），**不要写任何需要查证的事实、年份、数据、人名、引文、品牌**；出现数字就标“示意”。不要画任何已有的角色、吉祥物、标志、作品画面，也不要模仿某个具体频道或作品的形象；人物用自己设计的简单形象。
- 规矩：任何文字不小于 32 像素；画面底部 120 像素是字幕带，不放文字；文字不压在别的文字或图形上；任何一段不要 4 秒以上完全不动；开场 1 秒内就有内容。

## 完成标准
1. `python3 ../kit/build.py check` 0 项不通过；提醒逐条处理或说明为什么保留。
2. 自己抽 5–6 帧（`stills`），用 Read 看图，确认：像这个风格、文字都读得清、没有重叠出画、不丑。发现问题就改，至少看两轮。
3. 把试验项目的四个文件拷到 `kit/gallery/<id>/`。

## 报告（简短，按这个格式）
1. 包文件路径、主题名、导出的每个函数的签名和一句话说明（我要抄进文档）。
2. 样片每一句演了什么；建议做回归定格的 5 个时刻（逗号分隔的秒数）。
3. `check` 最后的输出（原文）。
4. 你自己看图后仍然不满意的地方、这个风格目前做不到的事。
5. 发现的引擎或文档问题。

## 独立实现（硬规矩）
- 不要打开为参考而克隆下来的别人的仓库（参考项目只用来定风格规则，规则已经写进任务说明），也不要参照任何现成项目、频道、产品的代码、画面、角色、界面、标志。风格规则只以任务说明里写的为准，画法自己想、自己写。
- 界面、角色、图标、品牌名一律自己虚构，不要让人认出是哪个真实产品或作品。
- 每次运行命令都从你自己的目录 `<工作目录>/<id>/` 里跑；同时有别的人在做别的风格包，机器会慢，命令给足超时（stills 2 分钟、check 5 分钟）。

## 前一批同事踩过的坑（照着避开）
- 逐字出现的文字：整串登记一次（用 kit.js 的全局 `REC` 和 `recText(整串, x, y, 字号, 对齐)`），用遮罩或逐字透明度显现；不要每个字各调一次 `txt()`，检查会把每个字当成一段独立的文字。
- 阅读时长只算透明度 ≥0.8 的帧：一段文字的显示窗口要比“字数÷read_cps + read_pad”多留约 0.6 秒。跟着镜头进出画面的文字也会被计时，镜头别扫过还没到时候的文字。
- `sfx()` 要在 t≥t0 的每一帧都调（整片扫描每 0.1 秒才看一帧），不要只在某一帧调。
- 片尾 3 秒也算进“4 秒不动”：最后一句结束前 1 秒内还要有动作。开场 2 秒内必须有内容。
- 封面 `art(c,cx,cy,R)` 给的是另一张画布的画笔 `c`，而包里的组件画在全局 `g` 上：需要在封面里用包组件，就在包里提供一个 `on(ctx, fn)`，临时把画笔换成 ctx（带文字的组件除外）。
- 新项目第一次先跑 `python3 ../kit/build.py timeline`。
- 缩放进场、退场的文字：透明度要先降、尺寸后变，否则缩小过程中会被报“小字”。
- 镜头推拉平移时，文字会扫过底部 120 像素的字幕带，也会被检查提醒：排镜头时留出余量。
- 投影/阴影的 `shadowBlur` 不随画布变换缩放，镜头放大时要手动乘缩放倍数。

- 相交的形状要分别填色：两块叠在一起的形状放进同一条路径里 fill()，重叠处会被挖空或糊成一块；颜色不同就分开画。
