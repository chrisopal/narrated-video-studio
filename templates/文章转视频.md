# 文章转视频

把一篇已经写好的文章（公众号、网页、自己的稿子）讲成一条视频。难处不在“读进来”，在三件事：文章是给眼睛看的，视频是讲给人听的；文章里写的不等于是事实；文章不一定是你的。

整条流程还是 `流程.md` 那十四步，这份文档只讲前面多出来的几步，和每一步里因为“有一篇原文”而不一样的地方。

## 零、先问清楚这篇文章是谁的

开工前问用户一句，把答案写进 `brief.json` 的 `source_article.basis`。**这一项不能替用户猜**，检查会拦。

| basis | 是什么情况 | 能怎么用 |
|---|---|---|
| `own` | 用户自己写的，或自己公众号发的 | 随意改编；配图也是自己的就可以用 |
| `licensed` | 别人的文章，已经拿到书面授权 | 按授权范围用；`proof` 写授权人、范围、日期，凭证放进项目 |
| `commentary` | 别人的文章，没有授权，做的是介绍和评论 | 只能用自己的话讲它说了什么、说得对不对；原话短引、标出处；配图不用；画面上注明原文 |

标了“原创”的公众号文章，没有授权就照着做成视频、换个形式发出去，是侵权，不是“二次创作”。用户想做别人的文章又没有授权时，建议他要么去要授权（一条私信的事），要么做成 `commentary`：讲的是“这篇文章说了什么、我怎么看”，不是把文章念一遍。

不管哪一种，别人的文章都要在画面上注明出处：`source_article.credit` 那一句原样放进 `must_show`（片头或片尾清楚停留 2 秒以上）。

## 一、取文

```sh
python3 ../kit/article.py fetch https://mp.weixin.qq.com/s/……     # 也可以是另存的 .html，或贴了正文的 .txt / .md
```

它写出三样东西，放在项目的 `article/` 里：

- `article.md`：正文，带小标题、引文、列表、配图位置。**先通读一遍**，后面的事都以它为准。
- `article.json`：结构化的块（段落、标题、引文、列表项、代码、图片），文末的“往期推荐、关注我们”已经标出来不算正文。
- `source.html`：取到的原页面，留底。

取不到的几种情况，脚本会直接说原因：微信要求验证、文章已删除、只能在微信里打开。这时请用户在浏览器里打开文章另存为 `.html`，或者把正文贴进一个 `.txt`，再 `fetch` 那个文件。**全是图片的文章**（长图、截图拼的）读不出字，要先人工转成文字。

配图的版权在原作者。`python3 ../kit/article.py images` 只列清单；`--download` 才下载，下载前告诉用户并得到同意，要用进成片的逐张进素材台账。

## 二、内容分析

`fetch` 之后自动跑（也可以单独 `python3 ../kit/article.py analyze`），结果在 `article/analysis.json`，同时打印一份摘要：

| 项 | 给你什么 | 怎么用 |
|---|---|---|
| 篇幅 | 正文字数、照着念要几分钟 | 一篇五千字的文章照念要二十分钟，没人看。视频稿通常是原文的两到三成 |
| 结构 | 每个小标题下多少字、几张图、几个数 | 看作者把力气花在哪；视频不必照这个顺序 |
| 信号 | 数字、年份、引语、步骤词、比较词、极限词、代码块…… | 这篇文章是靠什么撑起来的：数据、故事、步骤，还是观点 |
| 题材建议 | 前三张题材卡，各带依据的词、风格、风格包 | 建议，不是结论。读完文章，看它**实际在回答什么问题**再定 |
| 强调色 | 文章自己用得最多的颜色 | 写进 `themePatch.a1`，成片和原文是一家的 |
| 画面机会 | 哪些句子适合大数字、图表、时间轴、对比、流程、引文卡 | 分场时的备料单 |
| 要核实的说法 | 带数字、年份、极限词、引语的句子 | 自动写进 `facts.json`，状态都是 `todo` |
| 原文给的链接 | 文章里的外链 | 查证时先看它们，是不是一手来源自己判断 |

脚本只会数和扫，**读懂文章是你的事**。读完用自己的话写下这张“论点树”，放进 `article/outline.md`：

```
一句话主旨：这篇文章想让读者相信什么 / 学会什么 / 记住什么
它在回答的问题：（读者带着什么问题点进来）
支点（3–5 个，每个一行）：
  1. 论点 —— 它用什么撑着（数据 / 例子 / 引用 / 推理）—— 最有力的那一个证据
  2. ……
作者的立场和口吻：（中立科普 / 有倾向的评论 / 推销 / 亲历）
文章没说、但视频观众会问的：
可以删掉的：（铺垫、题外话、重复、只对读者有用的排版话）
```

主旨一句话写不出来，说明还没读懂，或者文章本身就是几件事拼的——那就只取其中一件做，别硬凑。

## 三、从文章到视频稿：重讲，不是缩写

| 文章这样写 | 视频要这样讲 |
|---|---|
| 开头铺背景、讲缘起 | 前 3 秒就是钩子：最反常的那个事实，或读者最想问的那个问题 |
| 按作者想到的顺序 | 按观众要理解的顺序：先现象，后原因；先结论，后论证 |
| 一段讲透一个点，三四百字 | 一句话一个画面动作，一句不超过 60 字；一个点三到五句 |
| “如上图所示”“见下文” | 没有上下文：每一句自己立得住 |
| 小标题分节 | 章节条换成观众会问的问题（`chrome: question`），或干脆不要 |
| 长引文、整段数据 | 一句里只留一个数；原话只留最有力的一句，画面上打引号标出处 |
| 术语直接用 | 第一次出现用半句话解释，全片只用一个说法 |
| 结尾号召关注、转发 | 结尾回答开头的问题；片尾注明原文出处 |

篇幅按分析给的三档选：**精华版**（一分多钟，只讲一个结论和两三个理由，适合竖版）、**标准版**（两到四分钟，保留主线和每节最有力的证据）、**分集**（六千字以上的长文，按小标题拆，每集一个问题，第一集先讲全文的结论）。先定档，再按字数预算写，不要写完再砍。

然后照 `templates/叙事与创意.md` 走：拆出受众，写三个方向再选。文章已经有一种讲法了，三个方向里**至少有一个不照原文的结构**——往往那个更好。

## 四、风格怎么配

风格不是挑个好看的，是从文章里读出来的。按这个顺序定：

1. **题材卡**：看论点树里“它在回答的问题”，对到 `题材模板.md` 的一张卡。分析的建议是起点；一篇讲芯片的文章如果主线是“这家公司怎么活下来的”，那是企业或隐形冠军卡，不是科技卡。
2. **风格预设和风格包**：从那张卡推荐的里面选。再看文章靠什么撑着——
   - 靠数据：`chart`，图表为主，每张图一根主角；
   - 靠原理和机制：`lab` `space` 加 `morph`（形变）或 `whiteboard`（一步步画出来）；
   - 靠步骤和流程：`blueprint`、`iso`，工序条；
   - 靠故事和人：`archive`、`ink`，时间轴、引文卡；带笑点的第一人称用 `stick`；
   - 靠观点和判断：`kinetic`（动态文字）或 `host`（讲解员串场），观点要标是谁的；
   - 核查类：`dossier`。
3. **强调色**：用文章自己的主色（`brief.suggest.json` 里已经填了 `themePatch.a1`）。文章没有主色、或主色和所选风格的底色撞了，就用风格自带的。
4. **语气和声音**：分析会给“口语、轻快 / 平实 / 书面、克制”。视频的语气可以比文章松半档，但不要换人设——严肃的行业分析不要配成段子。写进 `brief.voice`。
5. **每个支点配一种画面**：对着“画面机会”那张单子，给论点树的每个支点指定一个主组件（这一点用大数字、那一点用对比、那一点用流程）。相邻两个支点不用同一种，全片不超过四五种。

横版还是竖版：用户没说就问。精华版默认竖版（`platform` 写上），标准版默认横版再出一条竖版摘要。

## 五、查证：文章说的不等于事实

`facts.json` 里那些 `todo` 是文章里扫出来的说法，逐条处理，一条不处理检查就不过：

- 稿子里**不用**的：删掉这条。
- 要用的：去查。查到一手来源 → `verified` 写网址；只有文章自己这么说 → `opinion`，`note` 写“原文作者的说法”，稿子里说“文章认为”“作者说”；是引别人的原话 → `quote` 写出处；自己推算的 → `inferred`。
- 查出来文章**写错了**：视频里不要跟着错。`own` 的文章告诉用户原文有误；别人的文章，要么不讲这一点，要么直说“原文这里的数字和某某来源对不上”。
- 文章给的链接优先看，但“文章引用了某报告”不等于核实过，要点进去看原件。

`source_article.basis` 是 `commentary` 时，文章本身的观点全部按 `opinion` 处理。

## 六、检查多了哪一项

`brief.json` 里有 `source_article` 时，`check` 多一项 **原文依据**：

- `basis` 没填或不是那三个值 → 不通过；
- `licensed` 没写 `proof` → 不通过；
- 别人的文章，`credit` 没进 `must_show` → 不通过；
- 把旁白和原文逐字比：`commentary` 时有四分之一以上是照搬 → 不通过；有连着六十个字以上相同 → 提醒当引文处理；自己的文章照搬六成以上 → 提醒“这是在念文章”。

## 七、常见错

- 把文章从头念到尾，配几张标题卡——那是有声书，不是视频。
- 文章的小标题原样当章节，每章开头念一遍标题。
- 原文配图直接截进来当画面：一是版权，二是给眼睛细看的图在视频里两秒看不清。重画成会动的。
- 文章里的“据统计”“研究表明”没查就照说。
- 标题党的文章，视频标题和钩子跟着夸张；极限词检查会拦，但先别写。
- 长文想一条讲完，结果每个点都只有一句话。删掉三个支点，把剩下两个讲透。
- 忘了注明出处，或只在简介里写、画面上没有。
