# 口播片：一条录好的口播，配上跟着讲话走的画面

三条线里的第三条。讲解线是先写稿、再合成配音；宣传线是先定音乐。**口播线的声音是别人已经录好的**：出镜人对着镜头讲完了，节奏、用词、停顿都定了。我们做的是读懂他讲了什么，把人像固定在一个角上，其余画面按他讲的内容生成，讲到哪换到哪，再配上字幕和背景音乐。横版竖版都能出。

`brief.json` 写 `"mode":"talk"`，风格包 `talk`，题材卡是《题材模板.md》第 23 张。

## 一、流程（和十四步的对应）

| 步 | 做什么 | 命令或文件 |
|---|---|---|
| 1 | 拿到口播视频，放进项目的 `footage/`。问清：发哪里（定横竖版）、要不要剪掉停顿和口误、人像放左边还是右边、名字条和主题怎么写 | `brief.json`：`"mode":"talk"`，`"talk":{"file":"footage/x.mp4","speaker":"名字"}` |
| 2 | 转写，得到稿子草稿 | `python3 ../kit/build.py talk` → `script.json`（一句一行） |
| 3 | **读懂再动手**：通读转写，写论点树（一句话主旨、分几段、每段的要点和例子）。版面上的标题、阶段条、要点清单都从这里来 | `导演阐述.md` |
| 4 | 校对和粗剪：改错字、删口误和重复的句子、分章、标要变色的词 | 改 `script.json`，再运行一遍 `build.py talk` |
| 5 | 查证：他讲的数字和事实照样进断言台账；他的看法标 `opinion` | `facts.json` |
| 6 | 写画面：每一段配什么卡片，挂在哪个词上 | `scenes.js` |
| 7 | 检查、看图、出片 | `check`、`sheet`、`mix`、`render`、`final` |

没有配音和回听这两步：声音就是原声，逐字时间直接来自转写。

## 二、`build.py talk` 做了什么

第一次运行：把口播转成带时间的句子，写出 `script.json` 草稿，每行是 `{"id":"s3","ch":"","vo":"识别出的字","tts":"识别出的字","src":3}`。`src` 是转写的第几句。

改完 `script.json` 再运行一遍：

- **留下哪些句子就剪哪些**。整行删掉的句子（口误、“这个地方我重新说一下”）会从视频和声音里一起剪掉。
- **长停顿收紧**。相邻两句之间停顿超过 0.7 秒（`talk.max_pause` 可改）就在句尾留一点气口后切开；不到的连着取，不出剪辑点。
- 生成：`footage/_talk.mp4`（剪好的口播）、`audio/<句id>.wav`、`audio/words.json`（每个字的发音时刻，来自原声）、`assets.json` 里的 `talk` 片段并切片。
- 打印素材多长、剪成多长、删了几句、几个剪辑点。

改稿的规矩：

- **校对错字只改 `vo`，不动 `tts`**。`tts` 留着识别原文，逐字时间靠它对齐；`vo` 是字幕上显示的字。英文词、专有名词、同音字（它／他）最容易错，对着原声核。
- 不调句子顺序，不改写他的话。字幕是原话，不替人润色。
- `ch` 分章（阶段条用）；`hl` 写这一句字幕里要变色的词，一句最多一两个；`beat` 照常标。
- 剪辑点是硬切，人像会跳一下。删得多时先数一数剪辑点，太密就少删几句，或者跟出镜人说清楚。

## 三、版面

`stage()` 一次搭好整个版面，横竖版共用一份场景：

| | 竖版（9:16） | 横版（16:9） |
|---|---|---|
| 顶栏：名字牌、主题 | 最上面一行 | 左栏最上面 |
| 标题：两行，第二行强调色，全程不动 | 顶栏下面 | 左栏 |
| 卡片：顶上一条阶段条，下面是跟着讲话换的内容 | 中间，最大的一块 | 右边整块 |
| 口播画面：带名字条，全程在 | 卡片下面，左或右 | 左栏下面 |
| 要点清单：讲到一条加一条 | 口播画面旁边 | 左栏中间 |
| 大字幕：原话，关键词变色 | 口播画面下面 | 卡片下面 |
| 进度条 | 最底下 | 最底下 |

`side:'right'` 把人像换到右边。强调色跟主题走，换成出镜人或企业的颜色写 `themePatch:{a1:'#…'}`。

竖版的安全区：`"platform":"channels"` 缺省给底部留 576 像素，这套版面放不下。样片用的是 `"safe":[110,48,290,48]`（上、右、下、左），底下 290 像素不放东西。这是估的，发布前在 App 里预览，看标题文案和按钮盖到哪。

## 四、卡片里放什么

先定这一段的话是哪一种，再选块：

| 他在讲 | 用 | 例 |
|---|---|---|
| 一句观点、一句结论 | `big` 一句大字 | “它能替代的 / 是最便宜的那部分” |
| 几个并列的东西 | `tiles` 并排几格 | 构图、配色、挑不出毛病 |
| 几个角色、几类人各自怎样 | `rows` 一行一个，讲到谁谁亮，词一个个弹出 | 老板、中层、骨干 |
| 层次、阶段、递进 | `steps3` 台阶 | 规矩、选择、判断 |
| 问题和出路 | `verdict` 上面问题，下面结论 | 挑不出毛病 ≠ 好看 → 只是及格 |
| 数字、对比、流程、时间线 | 通用组件 `bigNumber` `barChart` `compare2` `flowSteps` `timeline`，画在 `R` 里 | 要有来源 |

`swap(t, R, [{at, fn}])` 按时刻换块。规矩：

- **时刻都从原声取**：`T('s6')` 是这一句开始，`at('s9','配色')` 是“配色”两个字说出口的那一刻。不写死秒数：重新剪过之后秒数全变，句子编号不变。
- **画面比话早半拍到，不晚到**。块在这一段第一句开始时换，块里的每一样东西在他说到那个词时出现。
- **卡片上的字是他话里的词**，压缩成几个字，不替他加观点。他没说的结论不上画面。
- 一段话换一块，一块停 4–12 秒。他一句带过的不单独做一块。
- 只留人像、不配图也是一种选择：讲故事、讲感受的那几句，卡片上放一句原话就够了。
- 要点清单是全片的提纲，三到五条，每条在那一段讲完时出现。

## 五、检查怎么读

`"mode":"talk"` 之后：

- 阅读时长按边听边看算（6 字/秒），最短 0.8 秒。报出来多半是块出得太晚，或者换得太早。
- 画面空档放宽到 8 秒（人像一直在动）。
- 配音回听自动通过（字是从原声识别的）；识别错没错靠你对着原声校对，检查查不了。
- 断言台账照查：带数字的句子要有事实指向。出镜人的看法标 `opinion`，`note` 写“出镜人的观点”。查不到来源的数字，列出来问出镜人，由他决定留不留，不悄悄配成图。
- 叙事线的提醒（没有 ask、结尾没回扣）说的是他讲的结构，改不了稿；可以转告出镜人，也可以靠删句子、调要点来补。

## 六、素材和权利

- 口播视频是出镜人自己录的，台账里是 `own`，`creator` 写出镜人。别人的口播、课程、直播切片不是这条线做的事。
- 画面上出现的别人的东西（截图、标志、照片）照旧过素材台账。
- 背景音乐是合成的铺底，旁白下自动压低；想要别的音乐由用户提供有授权的文件。

## 七、现在做到哪了

- 用一段 60 秒的合成口播（合成声音、占位画面，里面故意放了一处口误）跑通了全程：转写 27 句，删掉 4 句、收紧停顿后剪成 53 秒，出了竖版成片；横版只看了定格。
- **还没有用真人录的口播试过**。真实录音有口音、语气词、环境噪声、说一半改口，识别和断句会比合成声音差；剪辑点上人像跳不跳得难看也没见过。
- 样片 `kit/gallery/talk`（竖版）和 `talk_wide`（横版）只演示版面：仓库里不放视频素材，角上是占位的人像框，没有字幕。
- 版面只有这一套；人像全屏、人像和图各占一半这些版式还没做。
- 读懂内容、决定配什么图是 Claude 读转写后写的，没有自动生成画面的脚本。
- 长视频（十分钟以上）没试过：切片是逐帧存图，很占空间。
